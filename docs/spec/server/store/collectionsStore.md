# collectionsStore Spec

## 1. Overview

| Item         | Description                                                                                                                                                                                                                                                          |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Role         | Facade over the collection platform tables (`collections`, `collection_items`, `collection_exclusions`, `collection_grants`, `collection_visibility`, `collection_centroids`, `collection_tombstones`, `collection_digest_cursors`, `collection_merge_suggestions`). |
| Write rule   | Every journaled mutation executes through `actionJournalStore.commitChange()` — the change and its `action_journal` row land in ONE transaction under `lockManager`; the facade exposes no other public mutators.                                                    |
| Read rule    | The member view is the materialized `collection_items` set. Definition evaluation runs at write boundaries (upload hook / evolution reconcile pass) in the collections service; this store supplies reads and journaled membership mutators only.                    |
| Design owner | `docs/features/collections-platform.md` §3.1/§3.2 (lifecycle, members), §4.4 (merge suggestions), §4.7 (sharing), §4.8 (digest), §4.9 (evolution writes).                                                                                                            |

## 2. Implementation Spec

> **Layering (repository-contract):** `server/store/collectionsStore.js` is a facade — it
> contains no SQL and delegates to `CollectionsRepository` built over
> `storage.getExecutor()`. Dialect SQL lives in the twins
> `server/store/repositories/{sqlite,postgres}/CollectionsRepository.{sqlite,postgres}.js`.
> One repository interface covers the whole `collection*` table cluster
> (repository-contract rule 1, "one interface per domain"); the conformance suite groups
> cases per table.
>
> - **Source:** `server/store/collectionsStore.js`
> - **Interface + factory:** `server/store/repositories/CollectionsRepository.js`
> - **Conformance (L2):** `server/store/repositories/__tests__/CollectionsRepository.conformance.test.js`
> - **Facade test:** `server/domains/collections/__tests__/collectionsStore.test.js` (recentFiles precedent)
> - **DDL source of truth:** `server/store/postgresql/ddl/001_initial_normalized_schema.sql`
>   (PG-canonical; sqlite via the transpiler). This spec does not duplicate DDL text.

### 2.1 Journal discipline

Journaled mutators (domain `collection`, subject `collection:<id>` — undo-availability matrix
"create/add/exclude/pin/publish/rename/grant·revoke", archive, restore, merge-confirm side effects):

`createCollection`, `renameCollection`, `setPinned`, `archiveCollection`,
`restoreCollection`, `addItem`, `removeItem`, `addExclusion`, `removeExclusion`,
`setItemPublished`, `grantAccess`, `revokeAccess`, `setPublishMode` and the batch commands
`addItems` / `removeItems` / `mergeCollections` (§2.2 rows below —
one command journal row per call — batch publishes / multi-select add & exclude / merge-confirm).

Each one calls `actionJournalStore.commitChange(domain, subject, meta, inverse, mutation)`
with the row write implemented against the tx-bound repository (write methods take the
commitChange TX; `createCollection` resolves its `collection:<id>` subject inside the TX —
actionJournalStore §2.3). Batch commands (multi-select add / exclude / publish) produce
ONE command journal row whose payload carries the item-level inverse list. Journaled mutators additionally return the `actionId` undo pointer alongside
their §2.2 shape (routes surface it as `undo: { action_id }` — routes/collections.md).

**`subject_label` capture:** the `GET /api/actions` feed renders `subject_label` verbatim
and NEVER re-resolves it (routes/actions.md §2.4; the journal intentionally outlives its
subject), so EVERY journaled mutator captures `meta.subjectLabel` at commit time:

| Mutators                                                                                                                                                                                       | Captured label (at commit time)            |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `createCollection`                                                                                                                                                                             | created name                               |
| `renameCollection`                                                                                                                                                                             | the NEW name                               |
| `mergeCollections`                                                                                                                                                                             | the loser's name (subject is the survivor) |
| all others (`setPinned`/`setPublishMode`/`archive`/`restore`/`addItem`/`removeItem`/`addItems`/`removeItems`/`addExclusion`/`removeExclusion`/`setItemPublished`/`grantAccess`/`revokeAccess`) | the collection's current `name`            |

The name is read from the repository BEFORE the commit TX where the row is already
pre-read (`setPublishMode`, `removeItems`, `addExclusion` reuse their existing pre-read);
otherwise exactly one extra `getCollection` read per mutation. On a vanished subject the
label is captured `null` and the row still renders with its action label.
Conformance-safe: metadata only — no schema, no inverse, no fingerprint impact.

**Non-journaled mutators** (explicit exceptions, each with its design basis):

| Mutator                                       | Basis                                                                                |
| --------------------------------------------- | ------------------------------------------------------------------------------------ |
| `upsertDigestCursor`, `setVisible`            | visits/leave are self-reversing trivial state                                        |
| `setAutoPin` (`pinned_by='auto'`)             | additive, invisible, "no journal" (user touch of a system collection auto-pins)      |
| `clearAutoPin` (pass-6 reconcile)             | additive, invisible cleanup of an ILLEGAL auto pin; user pins never touched          |
| `upsertCentroid`, `deleteCentroids`           | derived math cache, never user-visible state                                         |
| `upsertMergeSuggestion`, `setSuggestionState` | proposal plumbing; the merge CONFIRM is journaled by the caller as the merge command |
| `addTombstone`                                | written inside the permanent-delete TX, not standalone                               |
| `deleteCollectionPermanent`                   | NO inverse exists (trash-parity); see §2.4                                           |

### 2.2 Main Methods — collections

Row shape returned by reads (domain-shaped per repository-contract rule 2):
`{ id, ownerId, name, nameLocked, origin, status, definition, publishMode, pinned,
pinnedBy, archivedAt, lastMemberChangeAt, createdAt, updatedAt }`.

| Method                      | Signature                                                                                            | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `getCollection`             | (collectionId) => Promise\<row \| null\>                                                             | Single-row read by id (any status; ACL rendering is the service's job).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `listForUser`               | (userId, { sort, status }?) => Promise\<row[]\>                                                      | Owner's collections + granted collections. `sort ∈ activity\|name\|created\|updated` in SQL; `status` filter defaults to `active`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `listArchived`              | (ownerId) => Promise\<row[]\>                                                                        | `status='archived'` for `__archive__` (order = `archived_at DESC`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `existsActiveName`          | (ownerId, name) => Promise\<boolean\>                                                                | Partial-unique probe (`(owner,name)` active); drives the caller's suffix-counter retry.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `createCollection`          | (input, ctx) => Promise\<row\>                                                                       | JOURNALED. INSERT; `origin ∈ system\|user\|seed\|search`, `publishMode` default `ask`. `ctx = { actor, actionId? }` passed to commitChange. ALSO seeds the creator's digest cursor (`upsertDigestCursor(tx, ownerId, id, created_at)`) INSIDE the same mutation TX — self-created collections never dot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

Sets `name_locked=true` when `lockName` (user rename).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `setPinned`                 | (collectionId, pinned, ctx) => Promise\<{ changes }\>                                                | JOURNALED. | `clearAutoPin`              | (collectionId) => Promise\<{ changes }\>                                                             | Pass-6 reconcile cleanup (`evolutionService` §2.9): clears `pinned_by='auto'` when the row is NOT a pinned `origin='system'` collection; `pinned_by='user'` is never modified. NON-JOURNALED.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `setPublishMode`            | (collectionId, publishMode, ctx) => Promise\<row + actionId\>                                        | JOURNALED. `publishMode ∈ ask\|off\|auto` — the explicit sharing-mode act. Owner-only enforcement is the service's job.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `archiveCollection`         | (collectionId, { actor }?, ctx) => Promise\<{ changes }\>                                            | JOURNALED. `status='archived'`, `archived_at=now()`. Used by both user archive and evolution pass 3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `restoreCollection`         | (collectionId, ctx) => Promise\<{ changes }\>                                                        | JOURNALED. `status='active'`, clears `archived_at`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `deleteCollectionPermanent` | (collectionId, { defFingerprint }?) => Promise\<{ changes }\>                                        | NOT journaled (no inverse): single TX under the subject lock — DELETE row (cascades items/exclusions/grants/visibility/centroids/cursors/suggestions) + INSERT `collection_tombstones` when `defFingerprint` given (system-origin only; permanent delete-from-archive is unrecoverable, trash-parity) + `actionJournalStore.purgeSubject('collection', 'collection:<id>')` in the same TX.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

Survivor keeps name/name_locked as-is; loser grants are dropped, never migrated (exposure expansion is always explicit). Caller (service) owns owner/active guards and the suggestion lookup. |

| Method                     | Signature                                                                                                            | Description                                                                                                                                                                                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `listStoredItems`          | (collectionId, { since }?) => Promise\<itemRow[]\>                                                                   | `{ collectionId, nodeId, addedBy, published, source, reason, createdAt }`; optional `created_at > since` for digests.                                                                                                                                                         |
| `getStoredItem`            | (collectionId, nodeId) => Promise\<itemRow \| null\>                                                                 | Single membership probe.                                                                                                                                                                                                                                                      |

| `addExclusion`             | (collectionId, nodeId, ctx) => Promise\<{ changes }\>                                                                | JOURNALED. | `removeExclusion`          | (collectionId, nodeId, ctx) => Promise\<{ changes }\>                                                                | JOURNALED.                                                                                                                                                                                                                                                                    |
| `listForNodes`             | (userId, nodeIds) => Promise\<{ nodeId, collectionId }[]\>                                                           | Membership-chip read (`POST /api/collections/for-nodes`): stored items of the user's visible collections.                                                                                                                                                                     |
| `addItems`                 | (collectionId, nodeIds[], addedBy, { published, source?, reason? }, ctx) => Promise\<{ added: nodeId[], actionId }\> | JOURNALED batch. ONE command row whose payload carries the item-level inverse list; idempotent per PK pair (conflicts report `changes: 0`, excluded from `added`); `touchMemberChange` runs INSIDE the same TX. Caller passes `published` and `source` explicitly.            |
| `removeItems`              | (collectionId, { storedNodeIds, excludeNodeIds }, ctx) => Promise\<{ removed, excluded, actionId }\>                 | JOURNALED batch. **Membership is materialized; this store exposes no definition engine.** The definition
engine (collections service) evaluates predicates/vector rules at write boundaries and
calls `addItems`/`removeItems` with the resulting diff. Read paths use
`listStoredItems`/`listForNodes` only. Member-row render states (normal / revoked /
trashed / purged) and join-time ACL remain service-layer concerns (precedent
`enrichRecentEntry`).

### 2.5 Sort and list semantics

- `activity` (sidebar default): `ORDER BY activity_score DESC, last_member_change_at
DESC, created_at DESC, id DESC`. The card list IS activity-score ordered;
  `last_member_change_at` → `created_at` remain as tie-breaker AND graceful fallback
  while `activity_score` is absent/all-zero (pre-rollup data).
- Every timestamp sort ends in `id DESC` (newest-first) as the final deterministic
  tie-breaker — tied second-granular/same-transaction timestamps must not yield a
  plan-dependent row order (routes/collections.md §2.4).
- `name`: locale-unaware `ORDER BY name` (both dialects); `created`/`updated`: timestamps
  DESC with the same `id DESC` tie-break.
- `similar` is not a SQL sort: service fetches the list and groups by centroid nearest-
  neighbor in JS (≤~20 rows) using `getCentroids`.

### 2.6 Transaction boundaries

- Every journaled mutator: `lockManager` lock + `executor.transaction`
  (mutation writes + journal INSERT) — owned by `commitChange`, never re-opened here
  (executor rule 3: transactions must not nest).
- Reads: no explicit TX.
- `deleteCollectionPermanent`: TX + subject lock constructed directly (no commitChange —
  there is no inverse to record; the same TX purges the subject's journal rows — permanent
  delete is unrecoverable by contract).

### 2.7 Error contracts

- Reads of missing rows → `null` / `[]` (never throw).
- Guarded UPDATEs on missing/illegal rows → `{ changes: 0 }`.
- Unique/partial-unique/FK violations surface as `mapDatabaseError`-mapped errors at the
  repository boundary (route level maps to `serverErrors.collections.*`); duplicate-active-
  name on `createCollection`/`renameCollection` is the caller's suffix-retry signal
  (`existsActiveName` + pre-check pattern, repository-contract rule 4).
- No `getBackend()` branching outside the repository twins (CI grep-gate; stores and
  `domains/(collections|ai)/**` carry zero `CacheAdapter`/`operationProgress` imports —
  CODING_STYLE.md Express Patterns).

### 2.8 Dependencies

- `storage.getExecutor()` + `CollectionsRepository` (+ twins)
- `actionJournalStore` (`commitChange`, `purgeSubject`)
- `infrastructure/lockManager` (indirectly via commitChange; directly for permanent delete)

### 2.9 Verification Scenarios

- [ ] create/rename/archive/restore/pin/addItem/removeItem/addExclusion/removeExclusion/publish/grant/revoke each produce exactly one `action_journal` row in the SAME TX: a mutation that throws leaves NO journal row, and a forced journal failure rolls the mutation back
- [ ] batch addItem over 3 nodes (one command) writes 3 item rows + 1 command journal row whose payload carries 3 item-level inverses
- [ ] `addItem` is idempotent on the PK pair (second call → `changes: 0`, no duplicate, no journal row content change — the duplicate command still records its own row with an inverse that no-ops)
- [ ] `addItem` stores `source`/`reason` (default `manual`); rule-managed callers pass `source='system'` and the matched reason; both survive the read mapping
- [ ] `removeItem` deletes membership only — the `file_nodes` row is untouched; on a definition-driven collection the command also inserts the exclusion
- [ ] `addExclusion` on a `origin='system'` collection also sets `pinned_by='auto'`; on `origin='user'` it does not touch `pinned`
- [ ] Read composition sanity: `listStoredItems` returns exactly the materialized rows (all `source` values); exclusions are evaluation inputs, never a read-time subtractor
- [ ] Name uniqueness: insert `(owner,'X')` while another ACTIVE 'X' exists → conflict raised; an ARCHIVED 'X' with the same name does not conflict (partial index); `existsActiveName` reflects exactly this
- [ ] `deleteCollectionPermanent`: row + items + exclusions + grants + visibility + centroids + cursors + merge-suggestion rows gone (FK CASCADE); tombstone present when fingerprint given; prior journal rows for `collection:<id>` purged; second call → `changes: 0`
- [ ] `upsertCentroid` with a different `modelId` creates a second PK entry, does not overwrite the old-space row
- [ ] `grantAccess` twice with different roles replaces the role (single PK row); `collection_grants` is invisible to `permissionStore`/`aclService` reads (integration check in the permissions suite)
- [ ] `setVisible(hidden=true)` removes the collection from `listForUser` for that user only; `upsertDigestCursor` round-trips `getDigestCursor`
- [ ] `createCollection` leaves exactly ONE `collection_digest_cursors` row
      (user=owner, `last_visited_at` = the row's `created_at`) — same TX as the INSERT
      (undo/journal rollback removes both); `listDigestCursorMap(userId)` returns
      `{ collectionId: iso }` for seeded/stamped pairs and omits never-opened ones
      (conformance twin on sqlite + PG)
- [ ] `upsertMergeSuggestion(2,1)` and `upsertMergeSuggestion(1,2)` yield ONE row (pair normalization)
- [ ] `setSuggestionState` rejects `merged → pending` (`changes: 0`)
- [ ] L2 conformance (`CollectionsRepository.conformance.test.js`) on real sqlite (`test:ci`) AND real PostgreSQL (`test:ci:pg:adapters`): PK/CASCADE semantics, partial-unique `(owner_id,name)` active-scoping, `activity`-sort (`activity_score` desc +
      tie-breaker chain) ordering parity, JSONB (PG) vs TEXT (sqlite) `definition` round-trip, ON CONFLICT idempotency parity
- [ ] Facade parity: no SQL text in `collectionsStore.js`; all mutators route through the repository + commitChange (grep assertion)
