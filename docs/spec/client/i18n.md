# Collections/AI Client i18n Key Groups (target contract)

Key catalog for the collections-platform client specs (docs/features/collections-platform.md §4.4–§4.17; CODING_STYLE.md Express Patterns error-codes rule). **Placement:** single key-group catalog for the whole workstream — no per-module key docs under `docs/spec/client/`; each owning spec repeats only its own group.

## 1. Mandatory-both-locales rule

- Every key listed below exists in BOTH `client/src/locales/ko.json` and `client/src/locales/en.json` before the owning component ships (shared-contracts.md mirror rule; `serverErrors.*` mirror included). No raw key leakage fallback (FilePropertiesDialog locale rule precedent).
- UI strings are addressed via i18n keys; specs quote English canonical labels (the ko locale
  carries the Korean renderings). Every group below requires keys in both `en.json` and `ko.json`.

## 3. Special-form notes

- **Particle/counter copy (ko):** merge question + count lines ride the pure particle helper `client/src/utils/koParticleUtils.js` (see its util spec); en variants rephrase without particles. Never string-concatenate particles in components.
- **`result_ref`-driven strings:** none — opaque token, no rendering.
- **Undo mixed-result copy** (`11 undone, 1 skipped (state changed since)`) is ONE key with two params (useUndoToast §2.4 consumes server counts).
- `serverMessages` namespace: unaffected (journal/toast text is client-keyed; server never sends display strings for collections actions).
